# Extended Data Figure 1 — Danaini host use across a butterfly × plant-genus matrix

Code and data to reproduce Extended Data Fig. 1: host use across Danaini, drawn as a
butterfly-species × plant-genus presence/absence matrix aligned to a butterfly phylogeny
on one axis and a genus-level Apocynaceae + Moraceae plant phylogeny on the other.

The work is six notebooks in `code/`, run in order, split into two halves that share a
common set of folders:

- **Danaini tree (`code/1–3`)** — builds the Danaini butterfly species tree from NCBI
  sequence data. Its data live under the `danaini_tree/` subfolders.
- **Host-use figure (`code/4–6`)** — builds the plant tree, derives the host-use matrix
  from the HOSTS dataset, and assembles the final figure. Its data live under the
  `host_matrix/` subfolders.

All notebooks are run with the working directory set to `code/`; every data path is
relative to that folder.

## Part 1 — Danaini tree (`code/1–3`)

Self-contained workflow for building, validating, and filtering the Danaini species tree.

- **`1_pull_ncbi_data.Rmd`** — retrieves all 12 loci for every Danaini species + 3
  outgroup species from NCBI; runs a built-in smoke test first (stops if the key/network
  is broken), then writes the per-locus FASTAs and `occupancy_matrix.csv` to
  `input_data/danaini_tree/`, and the retrieval summaries to `output_data/danaini_tree/`.
- **`2_build_danaini_supermatrix_tree.Rmd`** — builds the multi-locus (≥1 locus)
  supermatrix tree from `input_data/danaini_tree/`: codon-aware alignment → automated
  QC/trim → partitioned supermatrix → IQ-TREE (run manually, see the notebook) → root on
  *Heliconius erato* → export newick + branch-support values + figure. Also writes the
  species × gene reference matrix of the chosen accessions. No network access.
- **`3_compare_to_chazot_and_filter.Rmd`** — validates the tree against Chazot et al.
  (2021) with a congruence figure, then prunes it to
  `input_data/danaini_tree/species_to_keep.txt` to produce the final filtered tree (drops
  *Tellervo zoilus* and species absent from the curated HOSTS dataset). The filtered tree
  is written **straight to where the figure reads it**, as
  `input_data/host_matrix/Danaini_in_HOSTS.newick`, together with its branch-support table
  `output_data/danaini_tree/supermatrix_ge1/branch_support_filtered.csv`.
- **`helpers/`** — shared `.R` functions, each with a provenance header (retrieval + codon
  alignment originate from Marianna Karageorgi; the automated QC, concatenation, rooting,
  export, and Chazot congruence are Naama's additions/adaptations).

### Running

External tools (MAFFT, IQ-TREE 3) live in the `danaini-phylo` conda env. An NCBI API key
is read from `~/.Renviron` (`ENTREZ_KEY=...`). Run each notebook from the `code/` folder,
top to bottom, in a fresh R session.

```r
setwd("<path>/Extended_Data_Figure1/code")

# Notebook 1 — retrieve (long, network-bound; the smoke test in §1 runs first and stops on failure)
rmarkdown::render("1_pull_ncbi_data.Rmd")

# Notebook 2 — align/QC/concatenate (knits cleanly even before the tree is inferred)
rmarkdown::render("2_build_danaini_supermatrix_tree.Rmd")
# then run the IQ-TREE command printed in §5 of that notebook, and re-knit to root/export/plot.

# Notebook 3 — congruence vs Chazot + final species filter
rmarkdown::render("3_compare_to_chazot_and_filter.Rmd")
```

To build the tree from sequence data already retrieved elsewhere, place that data under
`input_data/danaini_tree/` (the `ncbi_loci/`, `ncbi_outgroups/`, and `occupancy_matrix.csv`
layout above) and run notebook 2. To change which species survive notebook 3, edit
`input_data/danaini_tree/species_to_keep.txt`.

## Part 2 — Host-use figure (`code/4–6`)

- **`4_build_plant_tree.Rmd`** — assembles the genus-level Apocynaceae + Moraceae plant
  phylogeny (`input_data/host_matrix/Apo_Mora_phylo_tree/apocynaceae_moraceae_genus_tree.newick`)
  that orders the matrix columns. Only needs re-running when its source trees change.
- **`5_build_host_matrix.Rmd`** — converts the HOSTS host-record dataset into the
  butterfly-species × plant-genus associations and per-genus / per-species annotations,
  written to `output_data/host_matrix/`.
- **`6_plot_host_matrix_figure.Rmd`** — assembles the final figure from the prepared trees
  and tables, writing `visuals/host_matrix/Ext_Fig1_butterfly_x_plant.pdf`.

### Running

```r
setwd("<path>/Extended_Data_Figure1/code")
rmarkdown::render("4_build_plant_tree.Rmd")
rmarkdown::render("5_build_host_matrix.Rmd")
rmarkdown::render("6_plot_host_matrix_figure.Rmd")
```

## Handoff between the two parts

The butterfly phylogeny built in Part 1 is the tree the figure uses. Notebook 3 writes the
filtered Danaini tree directly to `input_data/host_matrix/Danaini_in_HOSTS.newick`, which
notebook 6 then reads — so no manual renaming is needed between the two parts. The host-use
coding in notebook 5 mirrors the ancestral-state reconstruction used in Figure 2, so
Extended Data Fig. 1 and Figure 2 rest on the same curated associations and tip ordering.
